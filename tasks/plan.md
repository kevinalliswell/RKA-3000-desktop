# RKA-3000 项目界面落地计划

## 目标与基准

以仓库根目录 `rka-3000-ui.html` 为最新视觉与信息架构基准，将现有 PySide6 主窗口改造成与原型一致的桌面工作台。沿用现有控制器、数据访问和设备网关；界面改造不得把 HTML 演示命令接到真实设备。

## 当前差距

- 当前程序只有 7 个横向标签页；原型有 12 个主入口和实验准备、设备、报告等子页面。
- 当前主题为蓝色顶栏和通用卡片，原型为深色/浅色两套仪器台设计、左侧分组导航、顶部状态与任务式页面。
- 当前真实业务层仅覆盖 N₂/H₂/CO 及部分运行控制。原型新增的 7 种气体、共用通道、紧急停气和管理员限值尚无可信的真机后端契约。
- 根目录 HTML 是用户提供的更新版源文件，保持原样；已有 `prototype/` 版本是上一轮交付。

## 实施方式

1. **桌面框架**：建立原型色彩令牌、左侧分组导航、顶栏状态和页面标题，保留现有 Qt 页面的控制器绑定。
2. **核心流程页面**：新增实时总览与实验准备；让准备页的样品信息、配方选择和检查记录进入现有实验启动流程，运行时展示真实状态。未验证的现场安全条件持续提示。
3. **管理与结果页面**：将原有配方、监控、历史、报警、设备、分析、日志和设置页纳入新导航；增加报告与帮助入口，报告操作调用现有服务。
4. **真机边界**：新增气体拓扑与互锁说明的只读 UI。原型中的手动调气、紧急停气、管理员上限和身份切换不能仅由前端模拟实现；对应控制入口在真实程序中保持禁用并说明原因。
5. **验证**：离屏启动检查导航、页面状态与控制器接线；运行现有测试；核对 README 与交付行为。

## 完成标准

- 启动后的桌面主窗口呈现原型风格的左侧导航、顶部状态、分层页面与浅/深色主题。
- 12 个主入口均可到达；现有可用功能仍由原控制器执行。
- 实验准备至少完成样品、配方、检查和确认的界面路径，数据不得在界面中假装已经写入后台。
- 真机尚不支持的气体控制明确禁用，不出现可误认为已执行的操作结果。
- UI 测试及现有回归测试通过，README 记录运行方式和边界。

## 风险

- 旧测试依赖 `MainWindow.tabs` 的 7 个标签，需要保留兼容接口或同步更新。
- 设备控制仍存在未完成的现场安全验证，界面不能代替硬件联锁。
- 本机磁盘空间不足以重新安装完整 PySide6；验证使用 Python 3.11 虚拟环境并复用本机已安装的 Qt 6.11 库。安装环境细节不进入项目依赖配置。

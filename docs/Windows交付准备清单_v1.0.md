- 文档版本：v1.0

- 适用范围：当前冻结版本的 Windows 交付准备

## 1. 当前目标

当前不是正式封版安装包阶段，而是完成 Windows 交付准备。

本清单回答三件事：

1. Windows 打包准备什么
2. 当前主要风险是什么
3. 交付前要检查什么

## 2. Windows 打包路径

当前建议路径：

1. 开发环境在 macOS 持续开发
2. 在 Windows 环境建立独立打包机
3. 使用 `PyInstaller` 生成单目录发布包
4. 用实际串口驱动和 Qt 运行库做本机验证

说明：

- 不建议直接在 macOS 上交叉打 Windows 包
- Windows 包应在 Windows 本机生成

## 3. 当前依赖风险

### 3.1 Python 与 PySide6

- 风险
  - Python 版本不一致会导致打包结果不稳定
  - PySide6 在 Windows 下可能带来额外 Qt 插件收集问题
- 当前建议
  - Windows 打包机固定 Python 3.10.x 或 3.11.x 一版

### 3.2 串口与驱动

- 风险
  - USB 转串口驱动在 Windows 客户机可能缺失
  - 设备 COM 号变化会影响首次使用
- 当前建议
  - 安装包之外，单独提供驱动说明
  - 首次运行前给出 COM 口检查指引

### 3.3 SQLite 数据目录

- 风险
  - 安装路径权限可能导致数据库写入失败
- 当前建议
  - 默认把数据库和导出目录放到用户可写目录

### 3.4 打包内容

- 风险
  - `.env`、Qt 插件、图表依赖、编码资源可能漏打
- 当前建议
  - 打包前明确资源清单
  - 打包后做一次离线启动验证

## 4. Windows 打包前置检查表

| 检查项 | 说明 | 是否完成 |

| Python 版本固定 | 打包机 Python 版本已冻结 | [ ] |

## 5. 交付前最小验证

交付前至少验证以下项目：

1. 应用可启动
2. 首页、配方页、监控页、设置页、历史页可打开
3. 可读取设备数据
4. 可下发参数
5. 可保存实验记录
6. 可查询历史
7. 可导出 CSV

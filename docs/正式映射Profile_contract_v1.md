# 正式映射 Profile `contract_v1`

## 1. 说明

本 profile 基于 [硬件规格书_v1.0.md](/Users/kevin/CodeWorkSpace/Python%20Projects/RKA/docs/硬件规格书_v1.0.md) 中 `4.3 建议寄存器映射` 和 `5. I/O 与联锁要求` 整理，用于当前主线的正式映射接入。

> 此 profile 属于旧单设备 Modbus/PLC 主链路，不是独立 TAIE、Azbil CPL 或电子天平的原生映射；参见[三设备通讯协议基线](三设备通讯协议基线.md)。

当前目标：

- 为 `ModbusRtuClient` 提供可切换的寄存器映射 profile
- 为报警系统提供统一的报警位、等级和联锁属性定义
- 为后续现场正式表冻结保留切换入口

## 3. 报警位定义

| Bit Mask | 代码 | 等级 | 联锁 | 描述 |
|---|---|---|---|---|
| `0x0001` | `ALM-0001` | `CRITICAL` | 是 | 超温报警 |
| `0x0002` | `ALM-0002` | `CRITICAL` | 是 | 超压报警 |
| `0x0004` | `ALM-0004` | `CRITICAL` | 是 | 可燃气体报警 |
| `0x0008` | `ALM-0008` | `HIGH` | 是 | 风冷异常 |
| `0x0010` | `ALM-0010` | `CRITICAL` | 是 | 急停触发 |
| `0x0020` | `ALM-0020` | `HIGH` | 是 | 热电偶/温度采集异常 |
| `0x0040` | `ALM-0040` | `MEDIUM` | 否 | 称重信号异常 |
| `0x0080` | `ALM-0080` | `MEDIUM` | 否 | 通信质量告警 |

未定义位：

- 自动生成 `ALM-XXXX` 代码
- 默认等级为 `HIGH`
- 默认按联锁型报警处理

## 4. 当前接入范围

- `Settings.mapping_profile` 默认使用 `contract_v1`
- `ModbusRtuClient` 通过 `DeviceMap` 读取/写入寄存器
- `MainWindow` 按 `mapping_profile` 解码报警位并判断是否联锁

## 4.1 运行控制字 MVP 约定

当前主线先按 MVP 约定 `0x0060` 的位语义：

| Bit Mask | 命令 | 说明 |
|---|---|---|
| `0x0001` | `start` | 启动运行 |
| `0x0002` | `stop` | 停止运行 |
| `0x0004` | `pause` | 暂停运行 |
| `0x0008` | `resume` | 恢复运行 |
| `0x0010` | `reset` | 联锁/故障复位 |

实现方式：

- 上位机按“脉冲写”方式下发控制字
- 即先写命令位，再回写 `0x0000`
- 若现场最终位定义不同，只在 profile 层调整

## 4.2 联锁状态字 MVP 约定

当前主线先按 MVP 约定 `0x0051` 的位语义：

| Bit Mask | 代码 | 说明 | 可软件复位 |
|---|---|---|---|
| `0x0001` | `ILK-0001` | 超温联锁 | 是 |
| `0x0002` | `ILK-0002` | 超压联锁 | 是 |
| `0x0004` | `ILK-0004` | 可燃气体联锁 | 是 |
| `0x0008` | `ILK-0008` | 风冷联锁 | 是 |
| `0x0010` | `ILK-0010` | 急停联锁 | 否 |
| `0x0020` | `ILK-0020` | 控制器闭锁 | 是 |

当前链路：

- 监控页显示联锁状态、运行控制字和急停状态
- 报警页显示当前联锁并提供“联锁复位”按钮
- 恢复实验要求满足：报警解除、报警确认、联锁清除、急停解除

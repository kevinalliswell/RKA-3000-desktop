# Emma 阶段验收报告 v1.0

## 1. 验收范围

本次验收覆盖 `codex/emma-experiment-engine` 分支的三轮增量能力：

- 实验执行引擎骨架接入
- 步骤设定点自动下发骨架
- 报警联锁中断、确认后恢复、下发失败回退与故障停机

## 2. 验收结论

验收结果：通过

结论说明：

- 执行引擎已经从“仅有步骤推进逻辑”推进到“可与通信层、UI、数据库联动”的可运行状态
- 报警触发时，实验会从 `RUNNING` 转入 `INTERRUPTED`
- 报警解除后，不会自动恢复；只有在报警确认完成后，操作员才可手动恢复
- 设定点下发失败时，通信层会优先尝试回退到上一组设定，并将实验落成 `FAULTED`
- 数据库终态已可区分 `STOPPED`、`COMPLETED`、`FAULTED`

## 3. 验收项

### 3.1 状态机

- 已支持 `IDLE / RUNNING / PAUSED / INTERRUPTED / STOPPED / COMPLETED / FAULTED`
- 中断状态下不会继续推进步骤
- 故障状态下实验进入终态

### 3.2 主窗口联动

- 启动、恢复、步切换时触发当前步骤设定点下发
- 报警触发时更新监控页状态并禁用错误恢复路径
- 报警解除且确认后，监控页明确提示“可恢复实验”

### 3.3 通信回退

- 写入新设定失败时，优先回退到上一组设定点
- 回退结果会通过异常和日志向上反馈

### 3.4 数据落库

- 实验终态可按场景持久化
- 故障和中断相关动作已写入审计日志

## 4. 验证结果

- `python3 -m pytest -q`：`20 passed, 1 skipped`
- `python3 -m compileall src tests`：通过

## 5. 主要风险

- 当前报警联锁仍基于报警字非零判断，尚未细分“提示/联锁/紧急停机”等级
- 当前回退策略基于“上一组设定点”，正式硬件联调后仍需确认各控制量的安全回退策略
- 当前尚未覆盖“步骤超时”和“采集异常自动转故障”两类保护

## 6. 下一步建议

- 接入正式寄存器表和报警字典
- 增加步骤级超时、温升不到位判定
- 增加采集异常转 `FAULTED` 的自动保护

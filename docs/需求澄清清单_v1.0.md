- 文档版本：v1.0

- 目的：在继续 Sprint 2 及后续开发前，先冻结需求边界、验收口径和架构输入，避免返工

## 1. 使用方式

本清单不是设计文档，而是需求确认文档。

建议逐项确认，并给出以下三种状态之一：

- `已确认`：需求已经冻结，可直接进入设计/开发
- `待讨论`：需求方向明确，但细节未定
- `暂不纳入`：不进入当前 MVP 或当前版本

## 2. 当前项目的核心判断

结合现有 PRD、合同口径和已实现功能，当前项目最容易产生偏差的地方有三类：

1. MVP 范围是否过大
2. 控制软件到底是“单设备闭环”还是“多设备联动平台”
3. 科学实验软件中的“算法分析/报告输出”是否属于当前版本必须项

如果这三类问题不先定清楚，后续的架构、UI、数据库和测试都会持续摇摆。

## 4. 实验流程澄清

- 问题

    - 配方执行
    - 联锁中断

- 状态

### 4.2 配方模型到底有多复杂

- 问题

    - 目标温度
    - 升温速率
    - 保温时间

  - 还是后面还要加入：

    - 称重终止条件
    - 气氛切换延迟
    - 水蒸气/分析仪联动

- 状态
  - `待讨论`

### 4.3 步骤完成条件怎么定义

- 问题
  - 当前实验步骤完成，是以“达到目标温度并保温完成”为准，还是还要支持其他结束条件？
- 待确认项
  - 温度到位阈值
  - 到位持续时间
  - 最大允许超时
  - 是否支持重量变化率作为结束条件
- 当前建议
  - 当前版本先固定为：
    - 温度达到阈值
    - 保温时间完成
    - 超时则故障
- 状态
  - `待讨论`

### 4.4 中断、恢复、终止的业务规则

- 问题
  - 当前系统是否允许：
    - 暂停后改配方再恢复
    - 联锁解除后从当前步骤恢复
    - 故障后从中间步骤重新开始
- 当前建议
  - 当前版本只允许：
    - 暂停/恢复继续当前步骤
    - 联锁解除后恢复当前步骤

# RKA-3000 桌面前端迁移方案

## 选型

采用 **Tauri 2 + Svelte 5 + TypeScript** 构建独立桌面窗口，保留 **Python** 业务、数据库、报告和设备协议层。macOS 用于开发，Windows 为现场交付目标。界面参考 `prototype/rka-3000-ui.html`，保留深色仪器工作台的导航、信息层级和状态语义。

| 方案 | 性能与体积 | 界面表现 | 本项目判断 |
| --- | --- | --- | --- |
| Tauri 2 + Svelte | 系统 WebView，前端包较小；仍须打包 Python 后端 | 可精确还原 HTML 原型，组件和动画自由度高 | 采用 |
| Electron + Web 前端 | 自带 Chromium，安装体积和内存基线较大 | 界面自由度高 | 不符合轻量交付偏好 |
| PySide6 / Qt Quick | 原生性能好，但 Python Qt 运行时和设计迁移成本较高 | 可实现，但原型的 CSS/交互需重做 | 保留为现行稳定程序 |
| Flutter + Python | 渲染性能好，视觉统一 | 需要 Dart 和额外 Python 进程，现有 HTML 原型不可直接复用 | 当前收益不足 |

性能目标不是单纯比较前端语言的运行速度。实验界面的主要风险在串口超时、采样入库、曲线更新和报告计算；这些任务应留在 Python 工作线程或独立进程，界面仅订阅有时间戳的状态。Tauri 命令通过后台线程等待 Python 桥接响应，界面线程不执行串口 IO。

## 当前实现状态

- `frontend/` 已拆为应用框架、通用组件及 12 个独立页面，具备配方编辑、实验准备与控制、历史分页、报警确认与解除、审计、分析、报告、设置和帮助。深色默认、浅色可切换，趋势使用 uPlot Canvas。
- `desktop_bridge.py` 继续采用逐行 JSON 请求/响应，现已开放 `sim_*` 仿真业务接口。新版 `sim_*` 表保存七气体配方版本、启动快照、采样、报警、审计和旧库来源；原 PySide6 三气路表结构不变。详细接口和状态见[新版桌面仿真流程与接口](新版桌面仿真流程与接口.md)。桥接强制仿真模式，不接受真实设备写命令。
- Tauri 持有 Python 子进程，专用线程串行处理桥接消息，UI 调用在异步任务中等待，设置 5 秒上限和有界请求队列；超时后终止失效子进程。发布构建将 Python 进程打包为资源，并将数据库放在系统应用数据目录。
- macOS 新版 `.app` 已完成本机打包；Windows 安装包已补构建工作流，仍须在 Windows 环境运行验证。原 PySide6 程序仍是现有完整实验工作流入口。新版仅提供**可持久化的仿真闭环**；页面明确区分仿真读数和真实设备在线，不把仿真回读当作现场许可。

## 推进顺序与验收

1. **界面完整迁移**：已实现 12 页及关键子页、明暗主题、确认弹窗和错误状态；仍需在 Windows WebView2 和现场 1024px 屏幕复核。
2. **业务桥接**：已实现仿真状态、配方版本、预检、实验转换、分页采样、报警、分析、报告和显式旧库导入；不完整或过期数据不显示为有效值。
3. **仿真实验闭环**：已实现准备、置换、反应、冷却、复核、归档和报告，以及暂停、离线、报警、紧急处置与重启待复核。离线测试覆盖主要状态转换；真实方法符合性尚未验收。
4. **现场通讯与安全**：独立设备轮询线程提供每设备和每通道的在线、最新有效值、采样时间及失效原因；现场地址、气体、量程和联锁清单完成核验后，再开放真实写入。验收：断线、超时、错站号、旧值、部分 MFC 离线不会误判在线；UI 主线程无串口阻塞。
5. **Windows 发布**：在 Windows CI/现场机打包 Python 子进程和 Tauri 安装包，验证 WebView2 依赖、串口权限、数据库目录、升级与回滚。验收：无开发环境可安装启动，完整实验和报告结果与原程序一致。

旧 PySide6 应用和原型在第 1–5 步期间继续保留。切换默认入口需要 Windows 包、业务回归及现场只读联调完成后单独决定。

# RKA 桌面端技术栈与架构说明 v1.0

- 版本：v1.1（在 v1.0 基础增补）
- 日期：2026-03-06
- 目标：为 PySide6 + SQLite3 + Modbus RTU 项目提供可落地研发规范

## 1. 技术栈

- 语言：Python 3.10+
- GUI：PySide6
- 数据库：SQLite3（内置）
- 工业通信：RS-485 / Modbus RTU（`pymodbus` + `pyserial`）
- 数据处理：`pandas`（导出与统计）
- 配置管理：`.env` + `pydantic-settings`
- 日志：`logging` + 轮转文件
- 测试：`pytest`

## 2. 分层架构

- UI 层（`ui/`）
  - 主窗口、实验页、设备页、报警页
- 应用层（`app/`）
  - 启动流程、任务调度、状态机
- 业务服务层（`services/`）
  - 实验执行引擎、采集服务、报警服务、导出服务
- 设备通信层（`core/`）
  - Modbus 客户端、设备抽象、寄存器映射
- 数据访问层（`db/`）
  - SQLite schema、Repository、迁移脚本
- 领域模型（`models/`）
  - Recipe、Experiment、Measurement、Alarm

v1.1 增补模块
- `services/export_service.py`：CSV/Excel 导出服务
- `ui/main_window.py`：配方编辑器、报警确认、导出入口、实时曲线

## 3. 并发与时序策略

- UI 主线程只负责渲染与交互。
- 通信轮询在后台线程执行（QThread/worker）。
- 采集周期可配（默认 500ms）。
- 入库采用批量写策略，减少 SQLite 锁冲突。

## 4. 数据库规范

- 数据库文件：`data/rka.db`
- 关键表：`recipes`、`recipe_steps`、`experiments`、`measurements`、`alarms`、`audit_logs`
- 索引建议
  - `measurements(experiment_id, sampled_at)`
  - `alarms(experiment_id, created_at)`

## 5. 错误处理与恢复

- 通信超时：最多重试 3 次，失败标记设备离线。
- 串口断开：自动重连（指数退避上限 10 秒）。
- 数据库异常：记录日志并保留内存缓存，恢复后补写。
- 联锁报警：上位机进入安全模式，仅允许确认与复位操作。

## 6. 代码质量基线

- 类型标注：核心模块必须加类型注解。
- 日志规范：关键流程使用结构化字段（设备地址、实验ID、错误码）。
- 测试基线
  - 单元测试覆盖：寄存器解析、配方校验、数据库写入。
  - 冒烟测试：应用可启动，模拟数据可显示与落库。

## 7. 部署与运维建议

- 开发环境：macOS/Windows（Python 3.10+）
- 打包：后续可用 `PyInstaller` 生成桌面安装包
- 现场部署：建议串口权限检查脚本 + 一键诊断工具

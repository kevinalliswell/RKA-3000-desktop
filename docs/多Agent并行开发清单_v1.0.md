# RKA-3000 多 Agent 并行开发清单 v1.0

- 文档版本：v1.0
- 日期：2026-03-18
- 适用仓库：`RKA-3000-desktop`
- 当前基线：桌面端 `v1.1.0` 脚手架已完成，具备配方编辑、实时采集、报警确认、CSV/Excel 导出基础能力

## 1. 目标

将项目拆分为可并行推进的工作面，减少互相阻塞，建立稳定的合并节奏，尽快从“可运行脚手架”推进到“可联调、可验收、可交付”的工程状态。

## 2. 多 Agent 协作原则

- 每个 Agent 只负责一个明确模块，避免跨层大面积改动
- 公共接口先冻结，再并行实现
- 所有 Agent 分支合并前必须更新 `README.md`
- 所有 Agent 分支必须通过测试、自检和代码评审后再合并
- 优先并行“低耦合、高产出”模块，高耦合模块由主控 Agent 统筹

## 6. 分支与合并策略

- 主分支：`main`
- Agent 分支命名建议
  - `codex/leo-comm-core`
  - `codex/emma-experiment-engine`
  - `codex/mia-ui-refactor`
  - `codex/ryan-data-export`
  - `codex/lily-test-ci`

- 每个分支只解决一个主题，避免混合提交
- 每次合并必须包含 README 更新
- 合并顺序优先级
  - 公共接口分支
  - 下游实现分支
  - UI 集成分支
  - 测试与文档收尾分支

## 7. 每个 Agent 的完成定义

- 代码通过本地测试
- 新增或修改功能有对应测试
- README 已更新
- 文档已同步
- 不引入硬编码魔法值
- 不破坏模拟模式
- 功能可在主窗口或测试中被验证

## 11. 结论

可以做，而且这个项目很适合多 Agent 并行开发。

最合适的方式不是“大家一起改主窗口”，而是按“通信、执行引擎、UI、数据、测试、文档/发布”六条工作面拆开，由主控 Agent 管接口和合并顺序。这样并行效率高，也更不容易把桌面端项目做成一团耦合代码。

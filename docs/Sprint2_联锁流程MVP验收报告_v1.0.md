# Sprint 2 联锁流程 MVP 验收报告 v1.0

## 1. 验收范围

本次验收覆盖 `codex/sprint2-interlock-flow` 分支新增的联锁流程 MVP：

- `0x0051` 联锁状态字定义与解码
- 监控页联锁状态、运行控制字、急停状态展示
- 报警页联锁状态显示与联锁复位按钮
- 恢复实验前置条件闭环

## 2. 验收结论

验收结果：通过

结论说明：

- 联锁状态字已经从“仅有寄存器字段”推进到“可见、可判断、可复位”的 MVP 闭环
- 恢复实验现在不再只看报警确认，还会看联锁是否清除、急停是否解除
- `reset` 动作已经成为联锁恢复链路中的明确步骤

## 3. 验收项

### 3.1 联锁定义

- 已支持 `contract_v1` 的联锁位定义
- 已支持联锁文本预览
- 已支持“是否允许软件复位”判断

### 3.2 UI 展示

- 监控页显示联锁状态
- 监控页显示运行控制字
- 监控页显示急停状态
- 报警页显示当前联锁并提供复位按钮

### 3.3 恢复规则

- 活动报警存在时不可恢复
- 未确认报警存在时不可恢复
- 联锁仍保持时不可恢复
- 急停触发时不可软件复位
- 只有“报警解除 + 已确认 + 联锁清除 + 急停解除”后才允许恢复

## 4. 验证结果

- `source .venv/bin/activate && python -m pytest -q`：`35 passed`
- `source .venv/bin/activate && python -m compileall src tests`：通过

## 5. 主要风险

- 当前联锁位定义仍为 MVP 版本，需等待现场最终位表冻结
- 联锁复位目前已接控制动作，但尚未覆盖 PLC 真正复位反馈的联调场景
- 急停恢复链路仍依赖外部硬件解除，UI 仅做阻断和提示

## 6. 下一步建议

- 补 PLC/控制器真实联锁反馈联调测试
- 继续推进执行引擎与运行控制字的自动联动

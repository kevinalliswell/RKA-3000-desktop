## 1. 路线图总原则

从现在开始，不再按“继续补功能点”推进，而按以下顺序推进：

1. 先做结构收敛
2. 再稳最小业务闭环
3. 最后做 Windows 交付准备

当前版本所有路线都必须服从以下边界：

- 不新增联锁闭环
- 不新增压力采集
- 不新增在线判据
- 不新增动力学分析
- 不扩展 Excel/PDF/Word

## 2. 当前阶段总目标

把项目从“已经可运行的原型”推进到“结构清晰、范围稳定、可继续开发”的状态。

## 3. 阶段划分

### 阶段 A：结构收敛

- 阶段目标
  - 把当前核心控制流程从 UI 层抽离
  - 建立 `controllers/` 与 `hardware/` 的正式方向
- 主要参与 Agent
  - `Alex`
  - `Iris`
  - `Emma`
  - `Leo`
- 本阶段输出
  - `controllers/experiment_controller.py`
  - `hardware/device_gateway.py` 的设计与最小落地
  - `main_window.py` 责任瘦身
- 本阶段不做
  - 不继续扩展报警/联锁功能
  - 不继续补正式控制字闭环
- 验收标准
  - 实验启停和流程收口不再主要依赖 `ui/main_window.py`
  - 读数和参数写入调用路径更清晰

### 阶段 B：最小闭环稳定

- 阶段目标
  - 让“配方 -> 读数 -> 参数写入 -> 记录 -> 查询 -> CSV”稳定下来
- 主要参与 Agent
  - `Ryan`
  - `Emma`
  - `Mia`
  - `Lily`
- 本阶段输出
  - 历史查询字段定型
  - CSV 导出链路收口
  - 首页 / 配方 / 监控 / 设置 / 历史页范围收敛
  - 最小闭环集成测试
- 本阶段不做
  - 不增加 Excel/PDF/Word
  - 不新增设备诊断页和校准页
- 验收标准
  - 实验记录可保存
  - 历史可查
  - CSV 可导出
  - UI 范围与冻结文档一致

### 阶段 C：文档与用户口径收敛

- 阶段目标
  - 把研发口径、用户口径、交付口径统一
- 主要参与 Agent
  - `Owen`
  - `Alex`
  - `Mia`
- 本阶段输出
  - 最小操作说明
  - 当前版本范围说明
  - 页面说明与用户流程说明
- 本阶段不做
  - 不编写正式实验报告模板
- 验收标准
  - 新人能按文档理解当前版本做什么、不做什么

### 阶段 D：Windows 交付准备

- 阶段目标
  - 为后续 Windows 交付建立可执行准备
- 主要参与 Agent
  - `Evan`
  - `Owen`
  - `Lily`

  - 不强行追求正式封版安装包
- 验收标准
  - 清楚知道 Windows 打包需要什么、缺什么、先做什么

## 6. 当前不建议推进的事项

以下事项即使有人提出，也建议暂缓到当前路线图之后：

- 联锁闭环
- 压力采集
- 动力学分析
- 正式控制字闭环
- Excel/PDF/Word 报告
- 报警页大规模扩展
- 设备诊断页
- 校准维护页

## 7. 风险提示

### 风险 1：结构收敛被功能扩张打断

- 表现
  - 一边说要重构控制层，一边继续往 UI 层加流程
- 处理建议
  - 所有新增流程先过 `Alex + Iris`

### 风险 2：当前版本范围再次膨胀

- 表现
  - 想顺手把联锁、报告、分析一起做
- 处理建议
  - 严格按 [功能边界表_v1.0.md](/Users/kevin/CodeWorkSpace/Python%20Projects/RKA/docs/%E5%8A%9F%E8%83%BD%E8%BE%B9%E7%95%8C%E8%A1%A8_v1.0.md) 执行

### 风险 3：Windows 交付准备过晚

- 表现
  - 最后才发现 PyInstaller、驱动、依赖有问题
- 处理建议
  - 在结构稳定后尽早让 `Evan` 介入

## 8. 下一步建议

如果按本路线图执行，最自然的下一步是：

1. 先启动 `Iris` 的控制层与硬件层边界设计
2. 再启动 `Emma` 的控制器抽离任务
3. 然后由 `Leo` 补设备网关最小骨架
